# Scylla Image

NAI 图片生成前端。纯静态、零依赖、零构建，可直接部署到 GitHub Pages，也可用本地 Node 服务运行。

## 两种运行方式

**GitHub Pages（浏览器直连）**

Settings → Pages → Source 选 **Deploy from a branch**，Branch 选 `main` + `/docs`。
（Pages 只支持仓库根目录或 `/docs`，这是站点放在 `docs/` 的原因。）

上游已开放 CORS，浏览器直接请求，无需任何中转服务。Key 保存在你自己的浏览器里。
所有资源引用均为相对路径，因此在 `user.github.io/repo/` 这类子路径下同样可用。

**本地（后端持有 Key）**
```bash
# 在 config/api-key.txt 写入 token，然后
npm start   # → http://127.0.0.1:3215
```
此模式下 Key 只由本机后端读取，不进入浏览器。前端会自动探测并切换。
需要 Node 18+，无需 `npm install`。

## Key 的存放与加密

首次打开会要求填写 Key，两种保存方式：

- **口令加密保存** — PBKDF2-SHA256（21 万次迭代）派生密钥，AES-GCM 加密后存入
  localStorage。之后每次打开输入口令解锁；解密后的 Key 只存在内存变量中。
- **仅本标签页** — 明文存 sessionStorage，关闭标签即消失，不落盘、无需口令。

关于加密边界，说清楚比说好听重要：

| 能防 | 不能防 |
| --- | --- |
| 他人翻看本机 localStorage | 页面遭 XSS 或恶意扩展在解锁状态下读取内存明文 |
| 浏览器配置同步外泄 | 解锁后有人 hook `fetch` |
| Key 被误提交进 git | — |

静态站点最终必须以明文把 Key 发给上游，这是原理限制，客户端加密无法消除。模型和
生成接口使用请求头；Scylla 的全局额度接口目前只接受查询参数。如果你不信任部署环境，
请使用本地后端模式，让浏览器完全不接触 Key。

顶栏「锁定」按钮的行为取决于保存方式：

- 口令加密模式 — 丢弃内存中的 Key，下次打开需重新输入口令。
- 仅本标签页模式 — 没有口令可验证，因此会直接清除 Key，需重新填写（会先确认）。
- 本地后端模式 — 浏览器从不持有 Key，按钮隐藏。

## 默认行为

- **描述可留空** — 不填写 Prompt 也可直接生成；填写时仍按原样发送，不做改写。
- **不缓存到服务端**（`cache: false`）— 每次都真实生成。
- **历史仅存于本次会话** — 保留最近 25 个结果及其完整参数，可点击缩略图回看、
  一键「复用参数」、单张删除或清空。**刷新后清空**（图片只在内存，不落盘）。
  清空和刷新前都会弹出确认，避免误触丢图。
- **不压缩**（`optimize: false`）— 返回全质量 PNG。开启后上游会转为 JPEG（有损）。
- **不改写 Prompt**（`transform_prompt: false`）— 不经过任何 LLM 处理。

## 从图片导入参数

- **拖到页面任意位置**即可读取：外部 PNG / JPEG，或直接拖动右侧历史缩略图。
  顶栏的导入按钮也可打开文件选择。
- 识别两种写法：NovelAI 的 PNG `Comment` 块（含 `zTXt` / `iTXt` 压缩形式与
  JPEG EXIF），以及 WebUI / A1111 的 `parameters` 块。
- 弹窗逐项列出读到的值，**默认全选、可单独取消**；未勾选的字段保持当前设置不变。
  图片里没有的字段（多数外部图没有模型与 CFG）、以及本部署不支持的模型或采样器，
  会明确写在弹窗里而不是静默忽略。
- 拖动历史图走的是会话里存的原始参数，而不是重新解析像素 —— 后者会丢失编码时
  被丢弃的信息，开启「压缩体积」后导出的 JPEG 更是完全没有参数块。
- NAI 的 `scale` 与 WebUI 的 `CFG scale` 都是引导强度，对应本站的 Scale。
  NAI 的 `cfg_rescale` 是 0–1 的另一个量，**不会**被写进本站 0–30 的 CFG。
- 采样器名会做映射（`Euler a` → `k_euler_ancestral`、`DPM++ 2M Karras` →
  `k_dpmpp_2m` 等）；无法映射时该行不出现。

## 串行批量与生成锁

- 参数面板可设置一次生成 **1–24 张**。每张完成后才会提交下一张，不会并行请求。
- 生成按钮始终显示本次数量（`生成 ×N`）；运行时显示剩余数量并逐张递减。
- 留空 Seed 时每张使用独立随机 Seed；填写 Seed 时从该值开始逐张加 1（超过 uint32
  上限后回到 0）。
- 任意一张失败会停止剩余队列；「取消」会中止当前请求并清空尚未提交的队列。
- 页面会同时读取图片额度与临时 Key 全局日额度；图片已用大于 400 且全局剩余低于
  300 时显示警告。全局剩余低于 300 或额度暂不可用时，串行批量固定为单张；额度
  恢复后还原原设置。
- 批量结果依靠会话历史保存，因此生成多张时必须开启「加入历史」。
- 两张及以上全部完成后，会在浏览器本地合成一张带序号与 Seed 的网格对比图，
  作为最后一个历史项展示和下载；合成过程不会再次请求上游或消耗额度。
- 同一页面有显式任务锁；同源的多个标签页再通过 Web Locks 互斥。本地代理还在
  Node 进程中强制只允许一个上游图片请求，冲突请求返回 HTTP 429。

截至 2026-08-22，Scylla 的模型接口没有公布并发额度、速率限制或任务锁字段，
响应也没有 `RateLimit` / `Retry-After` 一类头；公开的文档路径未提供可读取的并发契约。
这表示 HTTP 层可以发出并行请求，但不能据此保证同一 Key 的并行任务会执行、排队还是
被拒绝。本站因此采用保守的单并发策略；它只能约束同源标签页和同一个本地服务进程，
无法替 Scylla 锁住其他设备或其他客户端。

## Danbooru Tag 词典

- 描述与排除输入框支持中文、英文 Tag 自动补全；按热度最多显示 20 条，浮层内可滚动。
- 顶栏或描述栏的「Tag 词典」可打开独立搜索页，支持中英匹配、分类与使用量展示，
  每页 25 条且可持续翻页；可复制单个 Tag 或打开对应 Danbooru 作品页。
- 点击搜索结果的名称区即可加入 Prompt 组合侧栏，逐项设置权重后可「复制」，
  或「应用到生成器」——组合会暂存到本地，回到生成器标签页时询问是否追加到
  描述末尾；确认后才写入，超过 30 分钟的暂存会自动作废。
- 组合保存在浏览器本地，刷新不丢；清空前会确认。
- 类型筛选会在搜索页和输入补全之间同步；通用、作品、角色默认开启，画师与元数据
  默认关闭，可按需开启。
- 左栏「编辑器」里可关闭 Tag 自动补全。关闭后会真正卸载监听，输入时不再向词典
  服务发出任何请求，也不再弹出候选；该开关独立持久化，不受「恢复默认」影响。
- 描述和排除栏的「清洗格式」会保留换行，清理转义下划线、HTML 空格与续行符，
  并将 `(tag)`、`((tag))`、`(tag:0.9)` 转为 NAI 数值权重；角色、作品和画师的消歧括号会保留。
- 双语结果来自 `tagsuggest.zeabur.app`，英文查询必要时回退 Danbooru 官方自动补全接口。
  查询词会发送给对应在线服务，不会携带 Scylla API Key 或生成参数。

## 只支持 NAI

模型列表从 `GET /v1/image/models` 动态获取并过滤为 `provider: novelai`。
上游同时公布了 Imagen 模型，但实测 `aspect_ratio` / `ratio` / `width+height` /
不带尺寸四种参数组合全部返回失败占位图，因此不予提供。

## 两个实测结论

**上游用 HTTP 200 表示失败。** 参数非法时（例如分辨率超限）返回的是一张
512×256 的 PNG，像素内容是「Generation Failed」字样。前端已按尺寸特征拦截，
并在提交前做分辨率守卫（NAI 上限约 1.05M 像素，即 1024×1024 或 832×1216）。

**seed 不保证可复现。** 两次 `seed` 相同、`cache: false` 的请求返回了不同的
图像数据。因此 seed 由前端生成并记录，仅用于溯源，不承诺重现同一张图。

## 移动端

单列布局，顺序为 图片 → 历史 → 控制项：

- 历史在图片下方变为横向缩略图条，可横滑
- 生成按钮吸底，44px 触控高度，避让 iOS home indicator（`env(safe-area-inset-bottom)`）
- 用 `dvh` 而非 `vh`，避免地址栏收起时的高度跳动
- 触屏下不显示悬停提示，改用 `aria-label`；删除按钮与图片元信息常驻显示
- 拖拽分栏在触屏隐藏（无指针可拖）

## 权重语法高亮

输入框会实时给带权重的片段上色（黑底：偏红=加权，偏蓝=降权，越亮幅度越大）：

| 语法 | 权重 |
| --- | --- |
| `5::text::` | 5 |
| `-5::text::` | −5 |
| `{text}` | ×1.05，可嵌套 |
| `[text]` | ÷1.05，可嵌套 |

`()` 不视为权重语法——真实 tag 本身就含括号（如 `sho_(sho_lwlw)`）。
