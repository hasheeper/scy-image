# 对话绘图页面与新版额度适配计划

日期：2026-09-10。状态：首版已实现；保留以下设计约束与接口勘探记录。验证范围见文末。

## 1. 目标与首版范围

- 修正现有 NAI 页的额度来源、费用预估、模型 ID 和串行保护。
- 新增 `docs/chat.html`，入口名称「对话绘图」。现有 NAI 工作区继续独立使用。
- 新页支持 GPT Image 2、GPT Image 2.5 Sunburst / Flare、Nano Banana 系列；实际可用模型从 Scylla 目录读取。
- 交互包含多轮连续改图、图片上传/粘贴/拖入、引用历史图片、质量与尺寸调整、版本回看、重新生成及下载。
- 延续纯静态 GitHub Pages 与本地 Node 代理两种部署方式、现有品牌和在线字体。
- 勘探阶段仅做研究与计划；实现阶段使用模拟响应测试，没有消耗真实出图额度。线上核验限于目录、额度和报价，编辑报价使用测试图片。

## 2. 已核实的接口与差异

| 项目 | 已核实事实 | 实现影响 |
| --- | --- | --- |
| 模型目录 | `/v1/image/models` 有 `provider_id`、`editor_family`、`quota_group`、`operations`、`image_capabilities.fields` | 两页共享目录读取，各自过滤适用模型，参数随能力变化 |
| 模型 ID | 目标模型 ID 带 `@local`；`/v1/media/models` 的 `id` 可能是展示名，真实标识在 `model_id` | 发送真实 ID，禁止用展示名拼接口；旧偏好按唯一匹配迁移 |
| 现有生成路径 | 公共文档仍支持 `POST /v1/image/generate`；官方 Studio 前端现已使用 `/v1/studio/image/generate` | 「仍支持」不代表新旧认证及计额完全一致，迁移前核验后再选定路径 |
| 官方 Studio 报价 | `/v1/studio/image/estimate` 使用 Bearer 可以读取报价；旧 `/v1/image/estimate` 也能读取 | 首选与执行路径配套的报价；禁止把一种请求的报价应用到另一种请求 |
| 改图 | 官方前端使用 `/v1/image/tools/estimate` 与 `/v1/image/tools/run`，`tool: "image-edit"` | 传 `init_image`、`additional_images`、`image_options`；非 NAI 参数不能沿用 NAI 白名单 |
| 价格保护 | `studio_features.version = 2`、`max_cost = true`；官方客户端把报价 `cost` 传回 `max_cost` | 每次执行绑定当前参数报价；免费额度不足时不能无声切换到付费 |
| 媒体额度 | `/v1/media/quota` 返回按周的 `images[quota_group]`、`weekly`、`credits` 和 UTC 重置时间 | 图次数、NAI 积分、临时 Key 日请求点数是不同指标 |
| 旧图片额度 | `/v1/image/quota` 不带模型，当前默认取 `novelai-v4.5` | 使用目录的 `quota_group` 读取，或显式传入真实模型 |
| 前端扣点 | `recordSuccessfulImage()` 每张自行减去 `rpd_units / rpd` 个临时点数；生成按钮也这样估价 | 删除这项费用推算，生成后读服务器余额；不能把临时请求单位当媒体费用 |
| 本地代理 | 只接受 NAI 正则，拒绝 `@local`；限制约 1.05M 像素、约 1MB JSON；遗漏 units 字段 | 共享目录校验和额度归一化；上传请求单独设置有界大小限制 |
| 原生会话 | Scylla 有 `/v1/responses`、Gemini `generateContent` 等路由，文档只声明一般会话契约 | 路由存在不证明图像工具、完整会话状态、签名或媒体计额已经贯通 |

另需修正上一轮结论的适用范围：公共 POST 出图接口没有被移除，但官方 Studio 已改走专用路径。不能仅凭接口仍有效，就认定新旧计费行为相同。

## 3. 成熟产品参考及采用的交互

已阅读 LibreChat 的图像生成/编辑文档、Open WebUI 的使用文档及其输入框截图，并核对 OpenAI、Google 官方多轮图像指南。

参考优先级：**当前 Scylla 页面决定视觉，成熟产品只提供交互参考，模型接口决定能力边界。** 新页是现有工作区的扩展，不是换皮或重新设计品牌；不能照搬外部产品的配色、聊天气泡、卡片或加载动画。具体视觉约束见第 4 节。

| 参考 | 采用的交互 | 在本项目中的处理 |
| --- | --- | --- |
| LibreChat | 会话式生成、上传后编辑、重复引用历史图片、消息版本 | 参考图有稳定资产 ID；每轮保存输入、参数和结果关系 |
| Open WebUI | 底部圆角输入框、附件入口、输入框内功能标签、结果下方小图标 | 模型/质量/尺寸使用紧凑选择器；下载与继续编辑置于图片下方 |
| OpenAI 图像文档与官方 Demo | 生成/编辑区分、图像预览、输出设置、支持时的渐进预览 | 原生能力与网关支持取交集；没收到进度事件时只显示等待状态 |
| Gemini 官方图像指南 | 对话连续修改、多图参考、图片与文本混合输出 | 模型适配器能够保留有序内容块；原生会话模式另行验证状态保留 |

LibreChat / Open WebUI 的完整 Agent 工作流会调用聊天模型和绘图工具。这里借鉴其成熟交互；首版用确定性的上下文整理直接调用绘图接口，不自动增加一个提示词改写或规划 LLM。

## 4. 新页布局

### 4.1 信息布局

桌面草图：

```text
┌────────────────────────────────────────────────────────────┐
│ Scylla  [NAI 绘图 / 对话绘图]          当前模型额度  菜单   │
├──────────────┬─────────────────────────────────────────────┤
│ ＋ 新对话    │                   会话标题                  │
│ 会话列表     │  用户指令 · 参考图缩略图                    │
│              │  大幅生成结果                              │
│              │  模型 · 参数摘要       下载 / 引用 / 重生成 │
│              │  后续修改指令与下一版结果                  │
│              ├─────────────────────────────────────────────┤
│              │ [本轮参考图]   上下文 · N 轮 / M 图         │
│              │ 输入描述或修改要求…                        │
│              │ ＋ [模型] [质量] [尺寸/比例] [更多]   发送  │
└──────────────┴─────────────────────────────────────────────┘
```

- 图片是主内容，按比例大幅展示；消息内容建议最大宽度 960–1120px，宽屏图片可以更宽，避免小聊天气泡包住大图。
- 输入框输入区自增高但有最大高度，内部滚动；附件横向滚动，删除按钮可触达。
- 常用参数留在输入框底行；格式、压缩、上下文选择等次要项放入「更多」。不把全部控件堆到右侧大面板。
- 用户消息保持简洁；图片下仅保留小字号模型与必要参数、统一 SVG 操作图标，不恢复冗长 TAG 栏。
- 生成中允许继续修改草稿；在途请求持有独立的参数和附件快照。滚动查看历史时不强行滚回底部。
- 手机会话栏收进主动打开的抽屉；图片近满宽，保留适当留白。参数栏空间不足时收进底部弹层，而不是缩小字号硬塞。
- 输入框跟随可见视口底部，适配软键盘与安全区；消息区按真实输入框高度留底部空间，最后一张图和操作不被盖住。

### 4.2 视觉原则：沿用当前 Scylla，不另起一套主题

基准为 2026-09-10 仓库现有 `docs/styles.css`、`docs/index.html`、`docs/js/app.js` 和 `docs/fonts/`。以下数值是当前实现的记录；后续共享变量是唯一来源，不在新页复制一套常量。样式注释存在旧实验残留时，以实际生效的规则和关键帧为准。

核心理念沿用现有样式文件开头的定义：**图片是画面的视觉中心，界面像托住照片的深色衬底。** 控件保持冷灰、低对比和轻微层次；“圆润、精致”来自统一字体、圆角、间距及克制的高光，不是增加装饰。

| 维度 | 当前基准 | 新页使用规则 |
| --- | --- | --- |
| 背景层级 | `--canvas: #131315`、`--chrome: #18181c`、`--raised: #1e1e24`、`--hover: #24242c` | 图片衬底用 canvas，输入栏/侧栏用 chrome，弹层用 raised；只差一个层级，不做明亮大卡片 |
| 输入凹面与边线 | `--well` / `--well-focus`、`--line: #1f1f25`、`--line-2: #25252e` | 复用弱边线和内凹关系；raised 容器内重新映射 well，避免输入框像深黑洞 |
| 强调与状态色 | `--a: #b3a1ff`、`--a-hover: #c1b2ff`；已有 ok / warn / err | 淡紫仅用于主操作、选中、焦点和等待反馈；模型切换不引入各厂商独立配色 |
| 文字层级 | `--fg: #e8e8eb`、`--fg-2: #a8a8ae`、`--fg-3: #86868d`、`--fg-4: #6a6a71` | 正文、辅助、说明逐级减弱；重要状态和正常小字不能使用仅适合装饰的 fg-4 |
| 字体与字重 | Manrope Variable + Noto Sans SC Variable；数字用 JetBrains Mono Variable；400 / 500 / 600 / 700 | 正文 400，标签 500，小标题/主操作 600，品牌 700；禁止全页加粗、合成粗体或另换“AI 风格”字体 |
| 字号 | 已有 11 / 12 / 13 / 15 / 18 / 22 / 28px 级别 | 正文/控件以 13px、主输入/操作以 15px 为基准；11–12px 留给摘要，不能把主体文字缩成元数据 |
| 间距与圆角 | 4 / 8 / 12 / 16 / 24 / 32 / 48px；圆角 5 / 7 / 10 / 15px | 使用现有 token；图片沿用 10px，输入容器/弹层沿用相应圆角，不把所有区域做成大胶囊 |
| 品牌与图标 | 现有 PNG 标识、白到淡紫的品牌文字渐变、现有 SVG sprite | 保留品牌大小字关系；参数/设置/模型/画幅沿用用户指定图标，下载等沿用现有操作图标，不用 emoji 替代 |

- 字体继续通过网站自己的 `fonts/*/index.css` 和 WOFF2 URL 在线加载，沿用预加载和 `font-display: swap`；不改成用户电脑上的 `local()` 字体优先，也不新增第三方字体依赖。
- 渐变只沿用现有品牌文字、主按钮和等待高光的用途；不新增整屏紫色渐变、霓虹外发光、彩色光团、厚重玻璃卡片或装饰性网格。
- 对话文字直接在安静的内容列排版，使用间距和轻量标签区分轮次；大图不套两层卡片、不被窄聊天气泡挤压。空会话沿用 `.blank` 的图标与一句提示，不添加示例填充或推荐词大模块。
- 图片沿用 `.print` 的薄边、收束阴影、完整比例展示和点击放大。图片下按「名称 → 模型 → 必要参数与小图标操作」组织；不恢复顶部结果栏、`RESULT 1 / 1` 或独立 TAG 文本栏。
- 底部输入栏沿用现有 composer 的底色、细边线和输入凹面；模型、质量、画幅是同一组紧凑控件，上传预览是附件，不另造一个显眼控制面板。

### 4.3 图片等待与加载：复用现有画框和动效

等待态的视觉来源是当前 `.print.skeleton`、`.bar`、`.sheen` 和 `.btn-go`，不是通用聊天应用的“正在思考”。以当前实际关键帧为准，不回退到历史上的水波或整面呼吸方案。

| 部件 | 当前效果 | 对话页约束 |
| --- | --- | --- |
| 暗色占位画框 | `.skeleton` 保持深色基底，带极轻的顶部明暗变化；继承 `.print` 圆角和阴影 | 每轮在结果位置预留画框，不用页面蒙层盖住历史，不靠提亮整块底色表示生成 |
| 顶部进度条 | `.bar` 高 3px；`barSweep` 每 1.5s 线性循环 | 保留小面积亮色扫光；无真实进度时不定进度，不显示模拟百分比 |
| 画框掠光 | 单道宽软光带，宽 56%、倾斜 14°；`sheenSweep` 周期 2.8s，前 52% 扫过，其余时间停在框外；峰值为 `--sheen-ink` | 保持“扫过一次—留白—再扫过”，底色不动；不增加多条同时行进的高光、旋转圈或整面闪烁 |
| 生成按钮 | 普通态淡紫轻渐变；busy 态保留 `--a-dim` / `--a` / `--a-line`，`goSweep` 每 1.9s 扫光 | 明确区分“正在执行”和“不可用”；运行中不能只变成灰色死按钮，保留可触达的取消入口 |
| 结果出现 | `.print` 的 `printIn`：380ms，淡入并从下移 6px / 缩放 0.988 恢复 | 解码就绪后轻量出现；不要飞入、弹跳或反复播放。切模型/改草稿不触发旧图片重入场 |

加载状态与尺寸约定：

1. 提交时冻结本轮尺寸、模型、附件和参数，并在该轮结果位置创建占位。已知尺寸按实际比例适配可用区域，不能套固定竖图模板；用户修改下一轮草稿不改变在途画框。
2. `auto` 尚无确定比例时，优先以主参考图比例占位，无参考图则用稳定方形占位；这只是布局估计，不当作结果尺寸。真实尺寸已知后只校正必要布局，并保持阅读位置，不把图片拉伸到估计比例。
3. 实际上传时可显示「上传中」，发起生成后显示「生成中」，收到图片后显示「图片加载中」。没有上游事件就不编造“排队第几位”、模型推理阶段、剩余秒数或百分比；阶段短文案放在按钮或画框外的状态位置，画框中央保持干净。
4. 从等待响应到下载/解码结束，画框连续保留当前等待样式；不是 HTTP 返回就移除占位。解码成功后在原位置切入图片，长图完整显示；失败进入该轮错误态，不能留下破图或把无图响应标成成功。
5. 连续改图保留上一轮完整结果，并为下一轮单独占位；不要把旧图模糊后当作新结果。历史/版本缩略图需要 pending 提示时沿用 `.tile-pending` 的淡紫边线与同一掠光，不另创动效。
6. 取消或失败立即停止该轮动画，保留指令和附件，用已有警告/错误色显示短提示及重试入口。取消不等于上游一定停止或退费；不能因此自动再发一次生成请求。
7. 使用局部 `aria-busy` 和 `role="status"` / `aria-live="polite"` 说明真实阶段；装饰光带对辅助技术隐藏，不按动画帧或秒数反复播报。
8. `prefers-reduced-motion: reduce` 沿用现有静态光带和静态细条，按钮停止扫光、结果停止位移动画；状态仍然清楚，不能将动画冻结在框外而留下空黑块。

### 4.4 移动端与共享实现边界

- 沿用当前 860px 的窄屏切换基准，再验证 320/390/768px；侧栏和低频工具主动点开，图片优先获得宽度。品牌、额度与菜单不因新增页面入口挤在一起；空间不足时把页面切换收进菜单，不继续缩小点数。
- 图片等待的顶部细条、暗色占位和单道掠光在手机上完整保留，不能以“简化移动端”为由全部隐藏。主操作与取消入口不被图片信息栏覆盖。
- 视觉图标保持现有约 16–20px 的尺度，触控热区至少 44px；不靠放大 SVG 或大按钮增加可点击性，也不让相邻热区重叠。参数弹层可内部滚动，关闭后恢复焦点。
- 输入栏响应 `visualViewport` / 安全区与实际高度变化；为消息列表同步预留底部空间。仅靠写死 `bottom: 0` 或固定高度不能作为键盘适配完成的依据。
- 实现时先提取共享主题、品牌、按钮、图框/等待动效和操作图标，再写 `chat.css` 的会话布局。新样式限定在聊天页面根容器内；不直接把整套 NAI 页面布局 CSS 搬入新页，也不复制一份主题长期分叉。
- 现有 `body[data-state]` / `#form[aria-busy]` 是单工作区状态，不能直接控制所有对话结果；提取为消息/请求级状态，保留相同视觉，避免一轮生成让历史图片一起闪动或消失。
- 本节是实现约束；公共样式已提取到 `ui.css`，图标提取到 `assets/icons.svg`。提取时回归现有 NAI 页，不能借新增页面重做旧页外观。

## 5. 上下文行为与数据模型

首版「上下文」明确指前端维护的绘图上下文：当前分支的历史文字指令、上一张选中的结果、固定参考图和本轮附件。

1. 首轮无图片：文生图；有图片：参考图生成/编辑。
2. 下一轮默认以上一张选中结果作为底图，保留相关历史文字；本轮修改指令放在最后，表示最新要求。
3. 输入框展示「上下文 N 轮 / M 图」，可以查看实际带入的文字与图片，指定旧图为底图、调整参考图顺序、固定、移除引用或重置上下文。
4. 新上传图默认持续带入：底图之外的图片留在上下文里，直到用户主动移除（移除必须粘住，不能在下一轮完成时被重新带回）。上一张结果自动成为底图，避免每次手动上传。
5. 从旧结果「继续编辑」创建分支；「重新生成」保留原结果并新增同级版本，不把失败或取消占位当作有效上下文。
6. 图片数量按网关和模型限制中更小的一项校验，底图也计数；超过限制时显示待处理项，不能静默丢图。
7. 上下文过长时让用户减少带入轮次或开新对话；不后台调用 LLM 摘要，也不默默改写用户指令。

建议数据结构：`Conversation` → `Turn(parentId, activeVersion, prompt, settingsSnapshot, inputAssetIds, status)` → `Result(assetIds, modelId, quote, usage, providerState)`。

- `Asset` 保存 Blob、MIME、尺寸、来源和稳定 ID；Blob URL 仅用于显示，发送时编码真实图片数据。
- 上下文资产与结果展示数量分开管理，避免用户限制历史张数后把下一轮所需底图释放。
- 首版延续既有「刷新后清空」策略，会话和图片在内存中；常用参数可本地保存。新页面不擅自开启图片长期持久化。
- 会话起名使用首条用户文本，不额外调用模型。默认同页切换工作区可保持会话的方案需在页面导航实现时确定；如采用真正页面跳转，必须有未保存会话提示或轻量交接机制，不能静默丢会话。

### 原生多轮会话的边界

- OpenAI 官方 Responses 路径支持 `previous_response_id` / 上下文结果引用，但需要主聊天模型调用 `image_generation`，官方明确其 token 费用另计。
- Gemini 官方当前指南支持 `previous_interaction_id`；使用 `generateContent` 方案时需验证有序 `contents/parts` 和必要的签名能完整回传。
- 首版连续改图不是上述服务端原生会话，不能在文案中声称完全等价。若后续启用「原生对话」，需独立的适配器、费用说明及网关联调，不静默降级或偷换模式。

## 6. 参数能力与模型适配

| 模型 | 当前上游允许的常用参数 | 兼容规则 |
| --- | --- | --- |
| GPT Image 2 | quality: auto / low / medium / high；size: auto / 方 / 横 / 竖；png / jpeg / webp | 不发送 NAI steps / sampler / CFG；不发送不支持的 input_fidelity |
| GPT Image 2.5 Sunburst / Flare | 以上基础上增加 xhigh / max | 两个独立模型 ID；切回 Image 2 时归一化超出范围的质量值 |
| Nano Banana | 比例；官方约 1024 级输出 | 不出现 GPT quality 选择，不许诺 2K / 4K；总输入图上限依模型限制 |
| Nano Banana Pro / 2 | 比例，1K / 2K / 4K | 大写 K；网关未列出的 512px 等不先行暴露 |
| Nano Banana 2 Lite | 网关列出 1K / 2K / 4K，但官方明确仅 1K | 已知冲突使用保守覆盖，只开放 1K，并注明其多轮/多参考适用性不同 |

- 目录声明为主，官方明确限制作为收紧规则；不能简单根据名称猜能力。
- GPT 自定义尺寸列为验证后开放：官方要求 16 的倍数、1:3–3:1、边长不超过 3840、像素数范围限制；网关当前只列预设，不能直接按 NAI 的 64 倍数处理。
- `image_options` 与原生提供商 `provider_options` 是不同协议，分适配器构造，禁止混传。
- 切换模型时保留兼容设置，明确显示被恢复到默认的选项；结果记录真实使用的模型与参数。

## 7. 费用与执行

- 共享模块区分：模型周图片额度、媒体 credits、临时 Key 请求限制。顶栏主指标绑定正在使用的绘图预算，详情可展开，不能把三者混成一个数。
- NAI 的免费/付费由报价决定；新页免费请求显示消耗张数，有积分报价时显示积分，费用未知就显示未知。
- 费用预览绑定模型、尺寸、质量、附件、操作类型和上下文快照；草稿变化后旧报价失效，防止迟到报价覆盖新参数。
- 首次发送、每个串行任务开始前检查相应预算；低额度保护应基于真实消耗。旧「剩余 300」规则暂不无条件移植到媒体周额度。
- 临时 Key 日额度是否仍影响不同生成路径，必须通过实际计费契约或受控联调确认；未确认前不能承诺“完全不扣 LLM 额度”。
- 新旧页共用同源 Web Lock，本地代理再加进程锁；报价查询不占长任务锁。
- 不自动重试生成 POST；取消、超时后不能承诺已退费。网络响应与图片解码都成功后才纳入可引用结果。
- 无真实百分比事件时用不定进度和阶段文字；只有上游真实支持时开启部分图片预览。

## 11. 实现与验证记录

- 上下文改为「原图＋结果」并存：此前 `mainId` 被每轮结果覆盖，用户上传的原图在第二轮就被挤出上下文，只有事先手动固定才能留住。改为区分两层——`keepIds` 是用户「要一直带着谁」的决定（与来源无关），资产上的 `origin` 是「上传还是模型结果」的事实；`contextSnapshot(c, prompt, limit)` 显式返回 `{base, refs, dropped}`，槽位 0 即请求的 `init_image`，不再靠数组顺序暗示。移除必须粘住（同时清出 `keepIds`），否则下一轮完成时会把用户刚删的图捡回来。
- 带图上限按模型能力分级并前置暴露：上限读 `min(供应商规则, max_context_images)` 而非按模型 id 硬编码；`prepare()` 改为裁剪而非抛错，切到窄模型是降级不是拦截，并立即提示丢几张。超额项在面板中保留展示并标注「超出上限，不带入」，输入栏对应缩略图灰显，入口按钮补 `−N` 计数——静默丢图是这次要修的核心缺陷。单图模型（Lite）下「添加为参考图」直接拒绝并指向「继续编辑这张图」。
- 上下文面板重做为操作台分区：容量计（`已带/上限`，超额转 warn 色）、底图槽（`--a-line` 描边 + `--well` 底，表示"座位"）、参考图列表（上移/下移/设为底图/固定/移除，首末禁用）、实际带入文字。图片来源与固定状态以徽标标注，统一由 `imageFacts()` 生成，避免输入栏提示与面板徽标漂移。窄屏下 44px 触控热区无法与缩略图同排，改为操作独占一行（实测 320px 原方案会裁切）。
- 额度计改为标注实际计量的池子：免费额度按 quota_group 归属供应商，显示该供应商名称与品牌图标（OpenAI 结绳／Gemini 与 NovelAI 四角星）；付费统一为跨供应商「积分」。对话页补上此前缺失的 data-level 分档，低量与未知状态下图标、数字、细条同步变色（品牌标记密度高，OpenAI 图标去掉光晕以免糊成一团）。
- 发送即消耗附件：随该轮请求进入消息区的引用行，失败或取消不放回输入栏（图仍可从上下文面板或引用行找回）。输入栏只显示用户本轮上传的图；主图（含自动链上的上一轮结果）只在上下文面板中显示与管理，可直接移除引用。生成中手动变更的上下文不被完成回调覆盖。
- 工作区、API Key、删除对话移到桌面顶栏，复用 NAI 的 34px 图标按钮；手机端通过顶栏入口折叠，展开后以 44px 图标放在会话列表前。去除侧栏底部按钮与说明；切换视口移动同一组控件，保留删除确认和 Key 对话框行为。
- 消息区移除「你／基于第几轮」、自动文件名、默认质量、重复免费标签及已选主图提示；仅保留内容、模型、尺寸和操作，付费费用仍显示。等待状态只保留一处，最新结果入口使用箭头图标；分支逻辑保持不变。
- 对话输入栏以发送箭头替代「生成」文字，进行中切换停止图标；附件按用户参考图简化为圆角缩略图＋右上角关闭，不显示文件名或操作排。主图、固定操作移入上下文面板；模型与参数值保留文字，图标保留工具提示、无障碍名称与手机触控热区。
